# Tin Can parent app (`ui/`)

React 18 + Vite + TypeScript. Mobile-first; parents open this on a phone. Talks to the backend
over the contract in [`../docs/api.md`](../docs/api.md).

## Scripts

| Command | What |
|---------|------|
| `pnpm install` | install deps (node 22, pnpm 10; `mise install` in this folder gets both) |
| `pnpm dev` | Vite on <http://localhost:5173>, proxying `/api` to `http://localhost:8080` (the backend) |
| `pnpm dev:mock` | same, but `/api` is served in-browser by MSW with seeded demo data; no backend needed |
| `pnpm test` | vitest + Testing Library, using the same MSW handlers in node |
| `pnpm lint` | eslint + `tsc -b` (strict) |
| `pnpm build` | production build into `ui/dist` (the backend image serves this) |

Mock-mode password is `tincan`.

## Structure

```
src/
  api/
    types.ts      TS types transcribed from docs/api.md (the only place shapes live)
    client.ts     fetch wrapper: `api.contacts.list()` etc., ApiError with the backend's error code
    hooks.ts      react-query hooks + query keys; mutations invalidate what they touch
    events.ts     SSE subscription to /api/events with a polling fallback; `useLiveUpdates()`
  pages/          one file per route (Home, Contacts, DialPad, Memories, Calls, Settings, Login)
  components/     Layout (bottom tab bar), Toggle, AudioPlayer, StatusPill, ErrorText
  lib/            format.ts (dates, durations, plain-words outcomes), errors.ts
  mocks/          MSW: data.ts (seed), handlers.ts (whole contract, in memory), browser.ts, server.ts
  test/           setup.ts, utils.tsx (renderPage with providers), *.test.tsx
  index.css       all styling; CSS variables with light/dark via prefers-color-scheme
```

Dependencies are deliberately few: react, react-dom, react-router, @tanstack/react-query. No UI
framework. Styling is one hand-written stylesheet with utility-ish classes (`card`, `row`, `btn`, …).

## How mock mode works

`src/mocks/handlers.ts` implements every endpoint in `docs/api.md` against an in-memory `db`
object seeded by `src/mocks/data.ts` (four contacts, six features, a dozen calls, five recordings,
status). The same handlers run in two places:

- **Browser** (`pnpm dev:mock`): `src/main.tsx` sees `VITE_MOCK=1`, starts the MSW service worker
  (`public/mockServiceWorker.js`, generated by `msw init`) and `startSimulation()`, which makes a
  fake call every ~45 s and pushes `call.started` / `call.ended` / `recording.created` over a real
  SSE stream at `/api/events`, so the Home page updates live. Audio URLs return a generated WAV
  tone so players and downloads work. `window.tincanMock` exposes `db` and `emit()` for poking
  from devtools.
- **Tests**: `src/test/setup.ts` starts `msw/node` with the same handlers and resets `db` after
  each test. Tests inspect `db` directly to assert what was sent to the "backend".

Auth: a 401 from any call dispatches a `tincan:unauthorized` window event; `App` redirects to
`/login`. The mock accepts password `tincan`.

## Adding a page

1. Add any new endpoint types to `src/api/types.ts` and methods to `src/api/client.ts`; add a hook
   in `src/api/hooks.ts` (and a key in `keys` so SSE invalidation can reach it).
2. Add the handler to `src/mocks/handlers.ts` (and seed data in `data.ts` if needed).
3. Create `src/pages/FooPage.tsx`; use `useFoo()` for data and `<ErrorText error={...} />` for errors.
4. Register the route in `src/App.tsx` and, if it's a top-level section, a tab in
   `src/components/Layout.tsx`.
5. Write `src/test/foo.test.tsx` using `renderPage()` from `src/test/utils.tsx`.

## Notes against the contract

- `POST /api/auth/login` response body is unspecified; the client ignores it and relies on the cookie.
- `/api/events` payloads are unspecified; the UI only uses event names to decide what to refetch.
- Speed-dial digits held by a feature are selectable when adding a contact (the backend is expected
  to replace the feature); digits held by another contact are disabled, and a 409
  `speed_dial_taken` is still shown in plain words if it happens anyway.
